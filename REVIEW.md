# Ревью календаря звонков

1. Сверь изменения с исходным обращением, согласованием человека, спецификацией и тикетами. Если материала не хватает, назови недоступную ссылку и вывод, который от неё зависит. Сопоставь проверки CI с SHA ревью и укажи их состояние.
2. Пройди по затронутым сценариям. Гость выбирает тип встречи и видит доступные слоты в часовом поясе календаря. Занятый слот исчезает из выдачи, параллельная запись на пересекающееся время отклоняется. После конфликта гость сохраняет введённые контакты и может выбрать другой слот. Владелец видит только предстоящие встречи в порядке начала. Списки сохраняют приватность email гостя и поддерживают одинаковые названия разных типов встреч.
3. Сверь тесты с основным, негативным и соседним сценариями из спецификации. При изменении API проверь соответствие TypeSpec и сгенерированных артефактов. При изменении workflow проверь полномочия токенов, допуск событий, защиту секретов и независимость проверки от правок.
4. Для каждого подтверждённого дефекта укажи путь и строку нового файла, условия воспроизведения и последствие. Учитывай предыдущие замечания и проверяй исправления на текущем SHA. Вывод линтера доступен в CI. При отсутствии подтверждённых дефектов так и напиши. Оставь решение о мерже человеку.
